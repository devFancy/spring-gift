# self-verification

작업 종료 시 사용자에게 결과를 보고하기 직전에 매번 자동 점검하는 룰. 코드 작업과 문서 작업 모두에 적용한다. 외부 지시(prompt.md 류) 없이도 동일한 품질 기준을 유지하기 위한 항목이다.

## 매번 점검할 7개 항목

작업 종료 직전, 다음 7개를 점검하고 어긋남이 발견되면 보고 전에 수정한다.

1. 산출물 목록 - 생성/수정/삭제 파일을 명확히 나열했는가.
2. 단일 책임 - 룰 파일, SKILL.md, references 가 각각 단일 책임을 유지하는가. 한 파일에 절차와 매번 적용 제약이 섞이지 않았는가.
3. formatting 룰 - 금지 특수문자(`—`, `–`, `→`, `·`, `§`, `…`) 미사용. 굵기가 한 문서당 1, 2개 이내. 사용자 노출 문구는 "요" 체.
4. 룰/스킬 역할 분리 - Rule 에 워크플로우 절차가 박혀 있지 않은가. Skill 에 매번 적용되어야 할 가드레일이 박혀 있지 않은가.
5. 패키지 위치 일관성 - 새 코드 또는 이동한 코드가 CLAUDE.md 목표 트리의 6계층(api/application/domain/infrastructure/storage/support/config) 안에 있는가.
6. 커밋 절대 준수 - `commit-discipline.md` 의 4개 항목을 위반한 곳이 없는가. Co-Authored-By 또는 AI 출처 표기가 본문 어디에도 들어가지 않았는가.
7. 회피 패턴 부재 - `@Disabled`, assertion 약화, try/catch 로 실패 삼키기 같은 회피 패턴이 새로 들어오지 않았는가.

코드 작업이 없는 문서 작업에서는 5, 7번이 자동 통과로 본다. 나머지는 문서 작업에도 적용한다.

## 보고 형식

점검 결과는 "산출물 목록 + 위 7개 점검 결과 한 줄씩" 형식으로 사용자에게 전달한다. 통과는 한 줄로 압축하고, 실패는 어디서 무엇이 어긋났고 어떻게 수정했는지 명시한다.

## 적용 제외

다음 경우 본 룰의 일부 또는 전부를 건너뛸 수 있다.
- 사용자가 명시적으로 "검증 생략" 을 지시한 경우.
- 한 줄 typo 같은 trivial 변경 (3번만 적용).

위 외에는 항상 적용한다.

## 도메인 단위 점검과의 관계

CLAUDE.md 7번 "룰/스킬 정리 정책" 의 정기 점검(도메인 리팩터링 완료 시)과 별개로, 본 룰은 모든 작업 종료 직전에 발동한다. 
도메인 정기 점검은 룰/스킬 자체의 정리에, 본 룰은 매 작업 산출물의 품질에 초점이 있다.
