# formatting

문서, 코드 주석, 사용자 응답 작성 시 적용되는 표기 규칙. AI 안티패턴 제거가 목적이다.

## 굵기 사용

- `**` 굵기는 정말 중요한 키워드 1, 2개에만 사용한다. 한 문서당 최대 1, 2개.
- 표 첫 컬럼을 굵게 처리하지 않는다. 표는 라벨이 이미 컬럼 헤더로 강조된다.
- 굵기를 강조 빈도 조절 용도로 남용하지 않는다. 일반 문장 강조용 사용 금지.

## 금지 특수문자와 대체

| 금지 | 대체 |
| --- | --- |
| `—` (em dash) | `-` |
| `–` (en dash) | `-` |
| `→` 및 다른 화살표 (`⇒`, `⟶` 등) | `->` |
| `·` (가운뎃점) | `,` 또는 `/` |
| `§` | 번호 표기 (예: "1번 항목") |
| `…` | `...` |

## 사용자 노출 문구

- 사용자에게 보이는 문구는 "요" 체로 작성한다. "니다" 체 금지.
- `해주세요` 붙여쓰기 금지. `해 주세요` 띄어쓰기 사용.
- `이에요` 보다 `예요` 형태가 자연스러우면 그쪽을 쓴다.

CLAUDE.md, 룰 파일, SKILL.md 같은 AI/개발자 대상 문서는 "다" 체로 작성해도 무방하다. "사용자 노출 문구" 는 chat 응답, skill 출력 메시지, 에러 메시지 등 사람이 직접 읽는 문구를 가리킨다.

## 트리 주석

- 프로젝트 구조 트리(`text` 코드블록)의 주석은 패키지/디렉토리 단위까지만 작성한다.
- 개별 클래스/파일 단위 주석은 금지. 필요하면 `*Service`, `*Repository` 같은 패턴으로 표기한다.

## 코드 주석

- 기본은 주석 없음이다. 식별자 이름이 의미를 설명하면 주석은 빼는 게 맞다.
- 주석은 WHY 가 비자명할 때만 단다. 숨겨진 제약, 미묘한 invariant, 특정 버그 우회 등.
- WHAT 을 설명하지 않는다. "현재 작업/티켓/호출자" 같이 PR 설명문에 들어가야 할 정보는 코드에 박지 않는다.
