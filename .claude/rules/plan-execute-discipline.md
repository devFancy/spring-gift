# plan-execute-discipline

사용자 명령을 받았을 때 Claude 가 따르는 작업 흐름 룰. 계획과 실행을 분리하고, 모호한 점은 코드를 건드리기 전에 질문한다. 매번 자동 적용된다. 본 룰은 `docs/private/plan-execute-playbook.md` (사용자 개인용 플레이북) 와 같은 정신이며 그 AI 측 명문화이다.

## 1. 모호함 확인이 먼저

사용자 명령을 받으면 작업 시작 전에 다음 4가지가 충분히 명확한지 자가 점검한다.

- 범위: 어디부터 어디까지 변경하는가.
- 우선순위: 무엇을 먼저 하는가.
- 검증 기준: "끝났다" 의 기준이 무엇인가.
- 자율 vs 합의: AI 가 자율 결정할 부분과 사용자 합의가 필요한 부분이 분리되어 있는가.

위 4가지 중 하나라도 모호하면 작업 시작 전에 사용자에게 질문한다. 질문은 객관식 또는 yes/no 형태로 1분 안에 답할 수 있게 짧게 만든다. 질문하지 않고 추측으로 진행하지 않는다.

읽기 전용 탐색(grep, 파일 읽기) 으로 1분 안에 해소되는 모호함은 직접 해소 후 진행해도 된다. 그래도 남는 모호함만 질문으로 만든다.

## 2. Plan 먼저, Implement 나중

명확해진 명령에 대해서도 비자명한 변경(2개 이상 파일 / 1개 도메인 이상 / 룰, 스킬 신설/수정)이면 다음 3단계로 진행한다.

1) Plan 제안: 변경 파일 목록, 각 파일 책임, 순서, 검증 방식을 사용자에게 먼저 제시한다. 코드는 건드리지 않는다.
2) 사용자 승인: 사용자의 명시적 승인("OK", "진행해", "그대로" 등)을 받는다. 승인 없이 다음 단계로 넘어가지 않는다.
3) Implement: 승인된 plan 만 그대로 실행한다. plan 에서 벗어난 변경이 필요해지면 즉시 멈추고 사용자에게 보고한다.

명백히 사소한 변경(한 줄 typo, 단어 치환, 단일 파일 한두 줄 수정)은 3단계 분리 없이 바로 적용해도 된다.

## 3. 자기 인터뷰

"해줘" 형태의 모호한 명령을 받으면 다음 순서로 응답한다.

- 자기가 이해한 작업 범위를 한 단락으로 미러링한다.
- 모호한 점을 5개 이내로 질문한다 (객관식/yes-no 우선).
- 답을 받기 전까지 코드는 건드리지 않는다.

질문은 한꺼번에 묶어서 한 번에 받는다. 작업 중간에 한 줄씩 묻지 않는다. 작업 중간에 새 모호함이 생겼다면 일단 진행을 멈추고 묶어서 다시 묻는다.

## 4. 적용 제외

다음 경우 본 룰을 건너뛴다.
- 사용자가 명시적으로 "묻지 말고 진행" 또는 "계획 생략" 을 지시한 경우.
- trivial 변경 (1번 적용 제외와 동일 기준).

위 외에는 항상 적용한다.
